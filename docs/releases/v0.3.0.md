# Intent v0.3.0 — the self-hosting release

> DRAFT for review. Nothing here is published: no git tag has been created and no
> announcement has been posted. Review/edit, then tag `v0.3.0` and publish when ready.

**Headline:** the Intent toolchain now self-hosts. The formatter, linter, checker, and
compiler are each written in Intent and produce output byte-identical to the original Go
implementation — proven end-to-end by a `stage1 → stage2 → stage3` bootstrap fixpoint.

This release spans ~300 commits since v0.2.0 (Feb 2026), taking Intent from a Rust-only
language to a multi-target, formally-verifiable, self-hosting toolchain.

## Self-hosting (Milestone 9)

- **The compiler compiles itself.** IR lowering and the Rust backend are reimplemented in
  Intent (Phases 55–56). `make bootstrap-stage3` verifies the full fixpoint: stage1 (Go)
  builds stage2, stage2 builds stage3, and stage3 re-emits the entire toolchain
  byte-identical to stage1.
- **Four self-hosted tools**, each byte-equal with its Go counterpart:
  `intentc fmt --self-hosted` (Phase 42), `intentc lint --self-hosted` (Phase 43),
  `intentc check --self-hosted` (Phases 45–54), `intentc build --emit --self-hosted`
  (Phases 55–56).
- **Emitter hardening (Phase 57):** the self-hosted emitter matches stage1 on *every*
  Intent program in the repo, not just the example corpus — `make diff-emit-sweep` 71/0/0.
- **Self-hosted checker completeness (Phases 48 & 53):** expression type inference plus the
  full type-rule check set — `make diff-checker` 104/104. Closing work in this release:
  spawn/try operand name-checking, the async-test-no-await warning (with warning-severity
  support), full `assert_eq` comparable-set parity, unary operator typing, method-call
  return-type inference (with type-param substitution), contract-clause name recursion,
  entity has-no-constructor, extern param/return unknown-type, and trait-method-contract
  formatter/linter fidelity. Remaining items are sound-false-negatives, catalogued in
  `prds/backlog/prd-phase-58-checker-parity-tail.md`.

## Multi-target code generation (Milestone 6, ADR 0009)

- A target-independent **IR** (ADR 0008) with one backend per target.
- **Three backends:** Rust (native binaries via cargo), JavaScript (Node/browser), and
  **WebAssembly** (direct emission). `--target rust|js|wasm`, `--emit` to write source.

## Verification & contracts (Milestone 5)

- **`intentc verify`** — Z3 SMT-based contract verification: preconditions, postconditions,
  entity invariants, quantifiers, and `intent`-block `verified_by` proof obligations.
- Contracts compile to runtime assertions in each target's idiom; `--strip-contracts`
  drops them for release builds.

## Language evolution (Milestone 7)

- User-defined **generics** (monomorphised), **traits** with static dispatch, **async**
  functions (spawn/await/fibers→tokio), `Map<K,V>`, `Char` + String indexing/slicing,
  closures/lambdas + `Fn` types, `Result`/`Option` + the `?` operator, enums with
  data-carrying variants and exhaustive `match`.
- **In-language testing** — `test "..." { ... }` blocks, run via `intentc test`.
- **Rust FFI** — `extern function … from "crate::path"` with boundary contracts.

## Developer experience (Milestone 8)

- **LSP v1** — diagnostics, hover, go-to-definition, completion, formatting, signature help,
  semantic tokens, and Z3 verification status; VS Code extension under `editors/vscode/`.
- **Package management** — `intentc pkg` with git-based dependencies and MVS resolution
  (ADR 0039).

## Upgrading

`intentc` takes its version from the git tag at build time (`-ldflags -X main.version`).
No source or config changes are needed to upgrade.

## Known limitations

The self-hosted checker has a documented tail of sound-false-negative diagnostics (it never
emits a wrong diagnostic and never fires on valid code) — see
`prds/backlog/prd-phase-58-checker-parity-tail.md`. The self-hosted compiler currently emits
the Rust target only; the JS/WASM backends remain Go-only.
