# Intent v0.3.1 — self-hosted checker parity + CI hardening

A patch release on top of v0.3.0 (the self-hosting release). No language or CLI changes;
this deepens the self-hosted checker's parity with stage1 and enforces the self-hosting
invariant in CI.

## Self-hosted checker (Phase 58)

- **impl-block-method contracts** — `intentc check --self-hosted` now checks the trait's +
  impl's `requires`/`ensures` on `impl` methods (well-typedness plus name / argument /
  operator recursion), matching stage1.
- **immutable-target checks** — per-binding mutability tracking in the checker, and the five
  stage1 diagnostics: cannot assign to an immutable variable, cannot assign to an index of an
  immutable array, and cannot call `push()` / `set()` / `remove()` on an immutable array/map.

`make diff-checker` is now **110/110** byte-equal with stage1 — the self-hosted checker
matches the Go checker across the example corpus and every invalid fixture, and the
`stage1 → stage2 → stage3` bootstrap fixpoint still holds.

## CI

- CI now runs the **full self-hosting parity suite** (`diff-*`, `selfcheck-*`, `diff-emit-*`,
  `bootstrap-stage3`) on every push to `main`, so the stage2 == stage1 byte-equality invariant
  is enforced automatically rather than only verified by hand.

## Housekeeping

- Retired superseded planning PRDs from the backlog.

## Known limitations

A small residual of sound-false-negative checker diagnostics remains deferred — built-in-method
return typing, extern FFI-bridgeability messages, the module-qualified `has no constructor`
variant, and the `@target_specific("wasm")` warning. None emit a wrong diagnostic or fire on
valid code. See `prds/backlog/prd-phase-58-checker-parity-tail.md`.
